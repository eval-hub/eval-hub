# Architecture Decision Records

ADRs describe significant EvalHub decisions using numbered files with context, decision, alternatives and consequences. A Proposed record does not imply an accepted or implemented feature.

## Index

- **0001 — reserved, not used.** The sandboxed evaluation runtime proposal in [PR 1059](https://github.com/eval-hub/eval-hub/pull/1059) was closed unmerged on 2026-10-19 without landing as an ADR. The number stays reserved and must not be reused for a different decision.
- **[0002 — Evaluation sandboxes through the internal OpenShell gateway](0002-evaluation-sandboxes-through-internal-openshell-gateway.md).** Proposed, 2026-10-19; revised 2026-11-19 and 2026-11-23. Decisions 2 and 4 record the model decided with the OpenShift AI architecture team: one static sandbox namespace for all evaluation job sandboxes in the driver's `shared` workspace namespace mode, one OpenShell workspace per EvalHub tenant, one sandbox per evaluation job. Decision 8 and the [gateway interaction contract](0002-evaluation-sandboxes-through-internal-openshell-gateway.md#gateway-interaction-contract-extension) keep sandbox execution off unless `spec.sandbox` enables it and a platform-published contract is qualified, and record the administrator bootstrap, the operator's reconciliation duties and the `SandboxedEvaluation` surface. References and analysis are aligned with PR 174 head `97a0c4d` (`ODH-ADR-Operator-0021`). The namespace-model record is still open across three outcomes for unclassified sandbox providers: PR 174 amended to `shared`, an EvalHub-scoped `shared` gateway, or supersession by a managed/operator variant. Acceptance gates are grouped by capability area, each with a named owner. [ADR 0003](0003-adversarial-cyber-evaluation-isolation.md) carves the adversarial cyber class out of decisions 2, 4, 6 and 7 and adds a fourth, class-scoped namespace outcome.
- **[0003 — Dedicated isolation for adversarial cyber evaluations](0003-adversarial-cyber-evaluation-isolation.md).** Proposed, 2026-11-27. Carves the benchmarks whose agent is asked to attack, escape or misuse its environment (`inspect/cybench` and `inspect/cybergym` today) out of ADR 0002's shared namespace: one run namespace and one run workspace per evaluation job on a class-scoped gateway, a simulated internet inside that boundary, mandatory Kata, no reuse across runs and verified namespace destruction after an accepted export. Every decision fails closed, the class is off by default, and the platform outcome, the namespace-controller ownership and the simulation-profile shape remain open. Decision 10 keeps per-run isolation scoped to the class, so the remaining agent benchmarks keep the shared sandbox namespace. It also records an [EvalHub-owned gateway deployment option](0002-evaluation-sandboxes-through-internal-openshell-gateway.md#deployment-option-an-evalhub-owned-gateway) — the second alignment outcome — without selecting it.

## Conventions

Use `NNNN-kebab-case-title.md` and the next unused number. Include status, date, deciders and references. Statuses are Proposed, Accepted, Deprecated or Superseded by ADR-NNNN. Preserve accepted history: add a successor and link the supersession rather than rewriting the original decision. Add each new record to this index.
